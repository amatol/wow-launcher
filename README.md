# WoW Launcher

Простой графический лаунчер для обновления клиента **World of Warcraft** (приватный сервер, 1.12 / 3.3.5a и т.д.).

Лаунчер обновляет файлы клиента в **папке, из которой он запущен**.

## Возможности

- **GUI на PyQt5** — атмосфера Нордскола, новости, прогресс загрузки; компактное окно от 720×400
- **HTTP/FTP обновление** — скачивает файлы из манифеста, проверяет SHA-256
- **Манифест-система** — JSON с описанием версий и файлов
- **Точечная проверка** — качает только изменившиеся файлы (по размеру/хэшу)
- **Самообновление лаунчера** — фоновая проверка, проверенная rename-then-replace замена EXE
- **Менеджер аддонов** — установка и обновление проверенных пакетов из одной или нескольких папок
- **Кнопка «Играть»** — запускает игровой `Wow.exe` из папки лаунчера
- **Первоначальная установка** — если отсутствует `Wow.exe` или каталог `Data`,
  докачивает ZIP клиента с Яндекс Диска, безопасно распаковывает его и затем
  запускает обычную проверку файлов по манифесту

## Структура

```
wow-launcher/
├── main.py                 # точка входа
├── config.py               # конфигурация (пути, URL, таймауты)
├── manifest.json           # пример манифеста обновлений клиента
├── launcher_manifest.json  # пример манифеста обновлений лаунчера
├── requirements.txt
├── core/
│   ├── version.py          # проверка/запуск игрового Wow.exe
│   └── self_update.py      # самообновление лаунчера (фон, rename-then-replace)
├── updater/
│   ├── manifest.py         # парсинг манифеста, проверка хэшей
│   ├── http_updater.py     # HTTP-скачивание с проверкой SHA-256
│   └── addons.py           # проверка и установка аддонов
└── ui/
    ├── main_window.py      # главное окно
    ├── widgets.py          # новости и прогресс-бар
    └── addons_dialog.py    # выбор и установка аддонов
```

## Установка

### Требования

- Python 3.10+ для разработки (для готовых сборок не нужен)
- Windows или Apple Silicon Mac с macOS 14+ и Rosetta 2

### Готовые версии Windows и Mac

Обновите лаунчер до выпуска 20261002 или новее и выполните обновление клиента.
Рядом с `Wow.exe` будут лежать `Dreamworld.exe` и готовый `Dreamworld.app`.
Установка второй платформы автоматическая; ZIP вручную распаковывать не нужно.
На Mac откройте `Dreamworld.app` из этой же папки. Встроенный Wine создаст
`.dreamworld-wine` в папке клиента при первом запуске, журнал запишет в
`.dreamworld-wine.log`. Обновление лаунчера сохраняет префикс и настройки игры.
При подготовке бутылки автоматически устанавливаются Microsoft `corefonts`
(Arial, Courier New, Times New Roman, Verdana и остальные шрифты набора).
Это работает и для уже существующей бутылки; нужен интернет при первой
установке. Winetricks и cabextract встроены, Homebrew игроку не требуется.
Tahoma и Tahoma Bold уже входят в Wine. Шрифты не меняют кодировку ввода;
результат проверки кириллицы нужно подтвердить на Mac.

macOS-версия тестовая: запуск бандла/Wine проверен на Apple Silicon в CI,
вход в игровой мир требует ручной проверки. Бандл пока без нотариализации;
инструкция первого запуска и сборки — [docs/SERVER.md](docs/SERVER.md).

### Установка зависимостей

```bash
pip install -r requirements.txt
```

## Запуск

Поместите `main.py` (или собранный лаунчер `Dreamworld.exe`) в отдельную папку
или в папку с существующим клиентом WoW, затем:

```bash
python main.py
```

## Настройка

### URL манифеста

В кнопке **«Настройки»** можно изменить URL манифеста обновлений.
Или отредактируйте `config.py`:

```python
MANIFEST_URL = "https://wotlk.amatol.blog/launcher/manifest.json"
```

### Формат манифеста

См. пример `manifest.json`:

```json
{
  "version": "3.3.5a-r1",
  "files": [
    {
      "path": "Wow.exe",
      "size": 10485760,
      "sha256": "e3b0c44298fc1c149...",
      "http_url": "https://.../Wow.exe"
    }
  ]
}
```

| Поле         | Описание                                      |
|--------------|-----------------------------------------------|
| `version`    | Версия патча. Если отличается — качаем всё.   |
| `path`       | Относительный путь внутри папки клиента       |
| `size`       | Размер в байтах (0 — пропустить проверку)    |
| `sha256`     | SHA-256 хэш файла (пустая строка — пропустить)|
| `http_url`   | URL для HTTP-скачивания                       |

## Как это работает

1. Лаунчер определяет свою папку как папку клиента (`Config.GAME_DIR`)
2. **В фоне** проверяет обновление самого себя через `LAUNCHER_MANIFEST_URL`
3. Проверяет наличие `Wow.exe` и каталога `Data`
4. Если клиент отсутствует, предлагает скачать базовый ZIP с Яндекс Диска;
   незавершённая загрузка сохраняется и продолжается при следующей попытке
5. Качает манифест клиента с `MANIFEST_URL`
6. Сравнивает версию манифеста с локальной (`.launcher_version`)
7. Определяет нужные файлы (версия отличается или хэш не совпадает)
8. Скачивает файлы по HTTP/HTTPS; при ошибке сообщает о ней и предлагает повторить попытку
9. Проверяет SHA-256 каждого скачанного файла
10. Создаёт бэкап существующего файла (`.bak`) перед заменой
11. После успеха — записывает новую версию
12. Кнопка «Играть» запускает `Wow.exe`

## Самообновление лаунчера

Лаунчер проверяет обновления самого себя в фоне при запуске:

1. Качает `launcher_manifest.json` с `LAUNCHER_MANIFEST_URL`
2. Сравнивает `version` с `Config.LAUNCHER_VERSION`
3. Если новее — показывает диалог «Доступно обновление»
4. При согласии — качает в `%TEMP%`, проверяет SHA-256 и размер
5. Rename-then-replace: переименовывает текущий `Dreamworld.exe` в `.old`
   и ставит новый на его место
6. Запускает новый процесс с чистым PyInstaller-окружением; он
   ждёт завершения старого до создания GUI
7. При следующем запуске `.old` автоматически удаляется
7. **Если обновлений нет или сервер недоступен — ничего не показывается**

### Формат манифеста лаунчера

См. `launcher_manifest.json`:

```json
{
  "version": "1.0.0",
  "download_url": "https://wotlk.amatol.blog/launcher/Dreamworld.exe",
  "size": 37748736,
  "sha256": "e3b0c44298fc1c149...",
  "changelog": "What's new"
}
```

## Сборка в .exe (опционально)

```bash
pip install pyinstaller
pyinstaller --onefile --windowed main.py
```

Штатная сборка выполняется через `Dreamworld.spec`; результат —
`dist/Dreamworld.exe`. Инструкция серверной публикации находится в
[`docs/SERVER.md`](docs/SERVER.md).

При обновлении клиента и установке выбранных аддонов лаунчер повторно
использует HTTP-соединения через общую сессию на время операции. Если сервер
закрыл соединение, следующее открывается автоматически. Проверки размера
и SHA-256, отмена обновления и повторные попытки сохраняются.
