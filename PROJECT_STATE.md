# Состояние Dreamworld Launcher

Последнее обновление: 2026-07-31

## Цель

Подготовить Windows-лаунчер Dreamworld и HTTPS-сервер обновлений для игрового
сервера AzerothCore из `/root/wowserver`, сохранив безопасную границу с
Telegram-ботом из `/root/telegrambot`.

## Постоянные решения

- Лаунчер называется `Dreamworld.exe`.
- Игровой клиент запускается только через `Wow.exe` (допустимы варианты
  регистра имени файла).
- Публичная база обновлений:
  `https://wotlk.amatol.blog/launcher/`.
- Эталонный клиент находится в `/opt/azerothcore/client`; файлы клиента не
  добавляются в Git.
- Публичная раздача хранится отдельно в `/srv/dreamworld-launcher`.
- Раздача обновлений статическая и не имеет доступа к MySQL, AzerothCore SOAP
  или локальному API Telegram-бота.
- Версии лаунчера и клиента имеют формат `YYYYMMDD`.
- Сначала публикуются файлы, затем манифест: манифест является последним
  атомарным шагом выпуска.

## Текущее состояние

- Репозиторий `amatol/wow-launcher` клонирован в `/root/launcher`.
- GitHub CLI авторизован как `amatol`; credential-файл имеет права `0600`.
- Локальная ветка `main` содержит ещё не опубликованные изменения; базовый
  подготовительный коммит — `f7d24db` (`prepare launcher update infrastructure`).
- В `.venv` установлены runtime/dev-зависимости; локально установлены
  библиотеки для headless-проверки PyQt5.
- Добавлены генераторы клиентского и launcher-манифестов, валидация путей,
  размеров и SHA-256, nginx-шаблон и тесты.
- Прошли 6 модульных тестов, импорт и headless-создание GUI. PyInstaller на
  Linux успешно собрал проверочный ELF; рабочий Windows PE собирает CI.
- nginx установлен, включён и слушает IPv4-порты 80/443.
- `/etc/nftables.conf` постоянно разрешает TCP 80/443; политика остальных
  входящих подключений остаётся `drop`.
- Сертификат Let's Encrypt для `wotlk.amatol.blog` выпущен и действителен до
  2026-10-29; `certbot.timer` включён и активен, staging-проверка продления
  `certbot renew --dry-run --no-random-sleep-on-renew` прошла успешно.
- Корень `/` намеренно возвращает 404. `/launcher/` раздаёт только GET/HEAD из
  `/srv/dreamworld-launcher`; listing отключён.
- Хранилище и папка `files/` созданы. Манифесты пока не опубликованы, чтобы
  незавершённый клиент не считался готовым.
- Клиент загружается в `/opt/azerothcore/client`. На последней проверке уже
  существовали `Data/` и `Data/ruRU/`; пользователь сообщит о завершении.

## Ближайшие шаги

1. Дождаться подтверждения полной загрузки клиента.
2. Проверить структуру, сборку 12340, `Wow.exe`, локаль и `realmlist.wtf` для
   `wotlk.amatol.blog`.
3. Определить, какие файлы являются эталонными и какие пользовательские файлы
   лаунчер не должен перезаписывать.
4. Сформировать `/srv/dreamworld-launcher/files` и реальный `manifest.json`.
5. Отправить локальный коммит в GitHub, дождаться Windows CI и скачать
   `Dreamworld.exe`.
6. Создать и опубликовать `launcher_manifest.json`, проверить HTTPS и
   самообновление на Windows.
7. При необходимости передать ссылку на лаунчер в Telegram-бот.

## Важные ограничения

- Не публиковать фиктивные или пустые рабочие манифесты.
- Не добавлять клиент WoW, сборочные артефакты, сертификаты и секреты в Git.
- Не открывать наружу `127.0.0.1:7878` (SOAP), `127.0.0.1:8080` (Dreamworld
  API) и MySQL.
